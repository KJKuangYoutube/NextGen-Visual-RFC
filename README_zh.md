# 基于 CMOS/SRAM 级数据裁剪的“3 秒硬件切片”与双路感知架构设计方案

*[Read in English (英文版)](README.md)*

**状态：** 征求意见稿 (RFC) / 概念架构白皮书  
**核心领域：** 片上计算 (In-Sensor Computing)、计算机视觉、自动驾驶数据工程、Web 原生多媒体  

---

## 序言：重构数据管线，回归物理源头

在当前的视觉计算体系中，我们陷入了一个巨大的“冗余陷阱”：传感器盲目捕获全量像素 $\rightarrow$ 庞大的冗余数据挤爆总线 $\rightarrow$ 消耗极高算力的视频解码器（VPU/ISP）将其压缩 $\rightarrow$ 播放或 AI 检索时再次耗费巨大算力解压。

**本方案提出一种全新的底层数据范式：将数据削减与特征提取的动作，直接倒推至光子转化为电子的物理源头（CMOS/SRAM 层）。** 

我们放弃传统的连续视频流（如 H.265/MP4）封装，改用以 **“3 秒硬件切片（1080p/4K 索引主图 + 物理微量矢量残差）”** 为基础单元的离散化架构。这种设计不仅契合 AI 时代大模型对“自带语义特征”的数据需求，极大降低了 Web 端传播的网络冗余，更因为其记录的是“物理真实残差”而非纯像素，从底层提供了极强的数据防篡改能力。

---

## 一、 核心架构：离散化的“3 秒原子切片”

彻底抛弃传统视频流“重容器、高耦合”的属性，将时间轴重构为一个个独立的 `.3s` 碎片文件。

每段 3 秒切片包含且仅包含两部分：

1. **索引主图（Index Frame）：** 1 张 1080p 或 4K 的标准原生 RGB 静态帧，用于视觉锚定与毫秒级检索。
2. **物理矢量残差流（Delta Stream）：** 传感器硬件层提取的后 3 秒真实像素位移与特征向量（极轻量，几百 KB），彻底丢弃全量中间帧像素。

在这种机制下，一段 1 分钟的动态记录，在文件系统中表现为 20 个独立且连续的原子切片。

---

## 二、 硬件源头层：3D 堆叠 CMOS 的“三步剔除”

数据的瘦身必须在离开芯片、进入总线前完成。我们在 3D 堆叠 CMOS 的逻辑层（On-chip SRAM/ASIC）硬化以下三条管线：

### 1. 硬件级 3D LUT 色彩量化（物理烘焙）

* **机制：** 不再向系统输出充满无用宽容度的 12/14-bit RAW 数据。在光子转电信号的瞬间，由片上 3D LUT 直接将其映射、量化为 8-bit sRGB 或 Log 曲线。
* **收益：** 提前“烧掉”肉眼和 Web 浏览无需的高光/暗部冗余色阶，源头体积削减 ~40%。

### 2. 动态门限滤波（Noise Gate 极值截断）

* **机制：** 设置底层物理掩模，当像素变化（如暗部热噪点、平滑墙面的微光闪动）低于人眼感知阈值时，硬件电路强制将这些微小波动归零（Zero-out）。
* **收益：** 消灭了导致视频码率降不下来的最核心元凶——高频随机热噪点。

### 3. 片上光流与块匹配引擎（In-SRAM Motion Engine）

* **机制：** 传感器进入降采样（Binning）模式。SRAM 内部直连的块匹配电路，将当前帧与索引图做像素级 XOR 异或比对。向外**绝对不输出完整画面**，只输出坐标位移矢量 $(dx, dy)$ 和发生有效变化的稀疏残差。

---

## 三、 封装与传输：无冗余的 Web-Native 数据包

传统的 MIPI 协议逐行发送像素，本方案采用自定义的**稀疏数据包封装**：

* **RLE（行程编码）与稀疏阵列：** 经过门限归零的无用噪点，在打包时转化为 `[位置, 连续0的数量, 压缩值]`，静止和冗余区域直接不占用传输带宽。
* **原生语义绑定：** 封装的不再是单纯的像素，而是带有空间运动规律的数学向量。
* **防篡改印记（Anti-Tampering）：** 由于记录的是 CMOS 物理层面的硬件异或矢量，而非 AI 脑补生成的像素，深度伪造（Deepfake）极难在保证物理光流合理性的情况下篡改该数据格式。

---

## 四、 软件渲染层：零解码的 GPU 驱动管线

摒弃系统层笨重的 VPU 视频硬件解码器，实现零延时、零卡顿的画面重现：

* **零拷贝直通显存（Zero-Copy DMA）：** `.3s` 文件的索引大图通过 DMA 直接载入 GPU 显存（VRAM），作为基础纹理（Base Texture）。
* **着色器纹理变形（Mesh Warping）：** 读取极轻量的运动矢量，调用 GPU 的 Compute Shader，像跑 3D 游戏一样，直接对主图网格进行微幅平移与光流补间。
* **播放体验：** 人眼看到的是无缝连续的动态画面，而系统后台完全没有“解压视频”的重负载开销。

---

## 五、 双路并行流水线（智驾与 IoT 的终极形态）

本架构天然支持在同一个传感器总线上，拆分出“给人看”和“给机器看”的双路流，完美解决机器视觉与视觉留存的冲突：

| 维度       | 通道 A：机器语义流（给 AI 看）               | 通道 B：切片视觉流（给人眼看）          |
|:-------- |:-------------------------------- |:------------------------- |
| **数据形态** | 3D 空间向量、占据栅格（Occupancy）、语义标签     | `1080p/4K 索引主图 + 物理差分矢量流` |
| **数据命运** | **看完即丢**：片上 NPU 提取文本特征后，原始像素彻底抹除 | **离散落盘**：打包为 3秒切片，用于回放与举证 |
| **管道开销** | 0 视频编码，总线仅传输几十 KB 纯数字文本          | 0 VPU 解码，依靠 GPU 纹理直接拉伸    |

## 六、 为什么这套架构是 AI 时代的必然？

1. **彻底解决海量数据检索痛点 ($O(1)$ 复杂度)**
   * 现在的自动驾驶或安防录像，要找特定画面必须逐帧解码长视频。
   * 本方案下，系统只需直接读取 `.3s` 切片头部的静态主图（仅占总体积的 2%~5%），无需任何视频解码，就能瞬间完成 VLM（视觉语言大模型）的场景分类与过滤。
2. **语义前置，拒绝“哑数据”**
   * 传统视频是无意义的像素堆叠（哑数据）。本方案在硬件层输出的物理“运动矢量”，本身就是绝佳的 AI 语义特征（记录了物体的运动轨迹和速度），拿来就能直接喂给大模型做时序预测。
3. **消除 Web 传播的宇宙级冗余**
   * 大众分享到网络的视频，绝大部分都是低信息量画面。在源头抛弃无用动态范围和多余帧，网络带宽和服务器存储压力将得到数量级的释放。

---

### 结语

不要再用算力去弥补传感器的贪婪。

将冗余剔除在源头，将语义提取在物理层，用离散切片取代连续长流。这不仅是一项图像压缩技术的迭代，更是视觉数据向大模型与高效互联时代演进的底层协议重构。
